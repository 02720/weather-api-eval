## 0. 本版先纠正三个事实

### 0.1 有效窗口只有 68 天，不是“三个月”

当前报告标签写的是 `2026-08-01 ~ 2026-11-01`，但 `data/obs/` 里四个站的实际观测都从 **2026-08-25T22** 开始，到 **2026-11-01T08** 结束，每站约 1,616 个小时，合计 **68 天**。8 月只有最后 6 天有数据。

这带来三个后果：

- v1 的“前后 15 天中心窗口”实际覆盖了数据跨度的约 46%，而且用了目标日之后的观测——这不是一个可操作的无技巧基准；
- 任何“气候平均”都只是**本站本窗口的平滑历史均值**，不是多年气候态。报告里必须这样写，不能写成“气候态”；
- 月度 `summary.json` 标的是整月，但当前 `data/obs/` 的原始观测不足以重建 8/1~8/24 的参照。新评分只能声明“可重算窗口 = 68 天”；若要复现整月结论，必须先从月度归档恢复观测，否则不要拿旧月报和新分数逐位对比。

### 0.2 桶级聚合和块级单元格不是一回事

评分管道有两套输入：

| 层级 | 用途 | 数据形态 |
|---|---|---|
| **桶级**（`_track_lead_boards`） | 分时效榜 `hourly:Nd` / `daily:Nd`、走势图 | 整个窗口按“提前 N 天”聚合，每家一个值 |
| **块级**（`_resolution_boards_blocks`） | 总榜、难度对齐、EB 收缩、bootstrap CI | 7 天日历块 × 天桶，每个格子一个值 |

v1 的“中长期 46~55”用的是**桶级**中位数；它把块与块之间的坏天气、坏样本都平均掉了。按块级单元格重算，14 天温度 RMSE 中位数是 **3.16°C**（不是桶级的约 2.8°C），14 天 `amt_mae` 中位数 **2.18**、最大 **1011.5**、**32% 的格子 >4**，ETS 中位数 **0.0**、**85% 的格子落在 ±0.05**。

所以 v2 的所有影子复算都分两层报：分时效榜用桶级，总榜/CI 用块级；不能混。两种层级还必须各自用**自己那份观测样本**算参照，不能拿一个全局 1.99°C 套所有层级。

### 0.3 中长期降水不是“回升”，是“没有可检出的技巧”

14 天块级 ETS 中位数 0.0，85% 的格子落在 ±0.05。把它们映射成 `50 + 50×ETS`，它们会全部堆在 50±2.5。这不是“模型有 50 分”，而是**这份 68 天存档无法证明任何一家在 8 天以上的降水上跑赢无技巧基准**。

正确的页面语言是：

> 本窗口未检出降水技巧（ETS 中位数 0.00，85% 的格子 |ETS|≤0.05）。

而不是“降水从中位 0~20 回升到 46~55”。后者是堆堆，不是技能。

## 1. 诊断：0 分是假的，但低分是真的

### 1.1 展示层先把下半段压成 0（v1 结论保留）

现行展示：

```
显示分 = 50 + gain × (原始分 − 50)，截断 [0, 100]
维度 gain = 1.744  → 原始分 < 21.33 显示 0
综合 gain = 2.863  → 原始分 < 32.53 显示 0
```

14 天小时榜 10/10 家降水显示 0，但桶级反算原始降水分为 10.4~17.0（中位 13.5）。这部分确实是假 0。

### 1.2 每个指标的 50 分不是同一个东西（v1 结论保留）

现行 λ 标定追求“子分跨源 sd=8”，不是“分数含义”。结果是：

| 指标 | 现行 50 分对应的真实值 |
|---|---|
| `ets` | 0.415 |
| `grade_ets` | 0.284 |
| `amt_mae` | 1.326 |
| `acc2` | 76.9% |
| `rmse` | 3.41°C |
| `r` | 0.720 |
| `slope` | 7.05 倍或 0.142 倍 |

温度 50 是“误差 3.41°C”，降水 50 是“ETS 0.415”，这两把尺子被各取一半做综合分。

### 1.3 固定绝对尺子 + 没有可操作的参照（v1 结论保留，参照要改）

现行 RMSE 到 6.8°C 永远 0 分，ETS 到 0.415 永远 50 分，和提前几天无关。16 天 3°C 误差与 1 天 3°C 误差被当成同一件事。

但“参照”不能用未来观测。v2 的参照必须**只用目标日之前的观测**，并且要报“参照敏感性”。

### 1.4 新问题：雨量比值无界，长时效会把“真 0”重新造出来

`amt_mae = Σ|预报−实况| / Σ实况`。分母趋 0 时比值发散。块级 14 天实测 0.99~1011.5，32% 的格子 >4。v1 用“4 倍 = 0 分”的线性段，会让这 32% 全部触底 0——**假 0 从展示层转移到了度量层**。

必须改成对数压缩，不能再用硬倍数。

### 1.5 新问题：MBE / slope / bias 不是独立技巧

- 14 天块级 74% 的格子满足 `|MBE| > RMSE/2`，长时效误差几乎全是常数偏置；
- `slope` 的 50 分对应 4 倍或 1/4 幅度，而真实分布大多在 0.6~1.0，这个子分几乎恒在 85~100，往综合分里注入一个“人人高分”的轴；
- `bias`（报雨频率比）与 POD/FAR 同源同一张列联表。

把它们和 RMSE/ETS 各自加权，等于把同一份误差数两遍。v2 把它们移到**属性层**，不参与技能综合分。

### 1.6 v1 自身的错误（必须承认）

v1 的“中长期 46~55”依赖三处结构性抬升，而不是度量改善：

1. 用**桶级聚合**而不是块级单元格，把长时效的坏块平均掉了；
2. 把 0~50 的下半段拉伸到 2~3 倍物理跨度（RMSE 3 倍/雨量 4 倍才算 0），让“比参照差 1.6 倍”的真实表现落在 35 分而不是 20 分；
3. 参照用“前后 15 天中心窗口”，用了未来观测，并把 68 天存档当成“三个月”。

v2 把这三处全部去掉。代价是**分数会更低**，但那是这份数据能支持的值。

## 2. 第一性原理：先问三个问题

### 问题一：这个数字给谁用？

| 用途 | 需要什么 | 不需要什么 |
|---|---|---|
| 同桶内谁比谁好 | 单调性 | 绝对刻度 |
| 比基准好多少 | 技能 `s = 1 − 误差/参照` | 人为的 0/100 锚点 |
| 一眼看过去强不强 | 绝对刻度 + 明确标注 | 把“无技巧”藏在 50 分里裸奔 |

v2 的回答：**主榜只回答第二个问题**（技能）；“谁比谁好”由名次回答；“强不强”由颜色/标注回答。不靠一个 0~100 同时承担三件事。

### 问题二：什么量可以做算术平均？

只有**同一物理量的线性可加近似**才适合直接加权平均。MSE/方差类满足；ETS 与量级比不满足；MBE 是误差分解的一支，不是独立证据。

v2 的回答：**先在技能空间归一化，再平均**。温度维内部用 `s` 加权；温度与降水在 `s` 空间各半；属性量单独列，不混进技能分。

### 问题三：0 分应该是什么？

不是“我想象的灾难倍数”，也不是“全错”。它应该是**观测到的最差尾部**，并且明确标注为显示约定。

v2 的回答：上半天 `50 → 100` 精确；下半天用指数压缩，**永不硬触底**；`0` 只留给“远差于本窗口最差尾部”的极端格。这样既不会把 32% 的雨量格误判成 0，也不会让“比参照差 1.6 倍”这种真实差表现凭空变成 35 分。

## 3. v2 方案

### 3.1 参照层：只用过去观测，不看未来，不回退到桶均值

**温度主参照（无技巧基准）**：

- 对每个站、每个目标小时/日期，用**目标日之前**的 W 天观测做平滑均值（默认 W=15）；
- 早于 W 天的目标，用“可用过去窗口”扩展（至少 5 天）；不足 5 天 → **参照不可用，不出分**；
- **绝不**回退到“该桶样本均值”——那个均值会让模型误差≈参照误差，分数恒等于 50，是自我实现；
- 报告 meta 记录 `ref_window=15`、`ref_effective_start`、`ref_sensitivity`。

**持续性对照（不是主锚点，但必须报）**：

- 逐小时：目标时刻 = 前一天同一小时观测；
- 日最高/最低：目标日 = 前一天日最高/最低；
- 持续性对照按桶分别算（同一个天桶内，目标日与前一天样本对齐），不能拿全窗口的 1.77°C 套所有桶；
- 在主榜旁边单独发布“持续性对照”技能分。若一家在长时效连持续性都跑不赢，页面直接标“不如持续性”。

> 为什么不用 `max(气候平均, 持续性)` 做主锚点：持续性是一个**有信息的真实预报**，不是“无技巧”。它的 RMSE 在这份存档里约 1.77°C，比气候平均 1.99°C 更强。如果把主锚点换成“两者中更好的”，50 分的含义会变成“不比最好的朴素预报差”，长时效分数会被系统性压低（14 天温度约 10~20）。v2 选择：**主锚点=气候平均（真正的无技巧）；持续性单独披露**。这既回应了“短时效可能虚高”的质疑，也不把主尺度换成另一个含义。

**降水参照**：

- 晴雨 ETS：0 = 无技巧；
- 雨强 `grade_ets`：0 = 无技巧；
- 雨量：参照 = “永远报零雨”，`MAE_ref = 平均观测雨量`。

**参照敏感性**：

- 用 W=10/15/30 各算一遍；若桶级中位技能变动 >5 分，报告标注“参照强度不足，绝对分只作方向参考”。
- 这是必报项，不是可选诊断。

### 3.2 度量层：主技能指标与属性指标分开

#### 温度主技能（进综合分）

| 指标 | 技能变量 `s` | 说明 |
|---|---|---|
| `rmse` | `s = 1 − RMSE / RMSE_ref` | 误差等于参照 → 0；完美 → 1 |
| `mae` | `s = 1 − MAE / MAE_ref` | 同上，作稳健复核 |
| `acc2` | `a≥a_ref`：`(a−a_ref)/(1−a_ref)`；`a<a_ref`：`(a−a_ref)/a_ref` | 命中率等于参照 → 0 |
| `acc1` | 同上 | ±1°C 补充点 |
| `r_anom` | `s = r_anom` | 扣掉气候均值后的异常相关；0 → 无技巧 |

#### 温度属性（不进综合分）

`MBE`（带符号）、`mbe_bdisp`、`slope`、原始 `r`。  
页面单列“偏差与形态”面板：如“系统性偏冷 1.8°C”“幅度 0.63 倍”“站间偏差 0.56°C”。  
它们回答“能不能用一个订正量修好”，不回答“比气候平均准多少”。

#### 降水主技能（进综合分）

| 指标 | 技能变量 `s` | 说明 |
|---|---|---|
| `ets` | `s = ETS` | 0 = 无技巧；1 = 完美 |
| `amount` | `s = 1 − ln(1+MAE) / ln(1+MAE_ref)` | 对数压缩；MAE=参照 → 0；MAE→大 → 负但被压缩 |
| `grade_ets` | `s = grade_ETS` | 中雨/大雨档技巧 |

`amount` 用对数而不是线性比值，专门解决 0.99~1011.5 的无界问题。举例：14 天某格 `amt_mae=4`、平均雨量 0.236mm/h → MAE≈0.944mm，`s≈−2.15`；它会被压到很低，但**不会和 1011 倍一起挤在 0**。

若该格 `Σ实况=0`（`MAE_ref=0`），amount 判缺项；ETS 通常也因无事件缺失，降水分判 `None`。不允许用“无雨格”的雨量项单独出分。

#### 降水属性（不进综合分）

`POD`、`FAR`、`bias`（报雨频率比）、`amt_bias`（总量比）。  
它们回答“多报还是漏报”，不再冒充独立技能。

#### 证据规则（关键改动）

- **ETS 是降水维的锚点，必须有**。ETS 缺失（例如整桶没有可评雨事件）→ 降水分判 `None`，绝不用“只剩 amount”凑一个降水分；
- amount / grade 缺失时，可按剩余权重归一，但前提是 ETS 存活；
- 不再用“至少 2 族存活”兜底——去掉 POD/FAR 后族结构变成 3 个单成员族，“至少 2 族”会让“amount+grade、无 ETS”的格子出分，这是风险叠加，不是收紧。

### 3.3 分数层：50 = 无技巧，下半段压缩但不硬触底

```
s ≥ 0：score = 50 + 50·s
s < 0：score = 50·exp(−k·(−s))
k = ln(10) / max(1, −P5(s))
```

- `s=0 → 50`，`s=1 → 100`；
- `s<0` 用指数压缩，永不为负，也永不硬触底；
- `k` 由标定窗口内**综合技能 s** 的第 5 百分位反解一次：把“本窗口综合最差的 5%”映到约 5 分，更差的尾巴逐渐趋近 0，但不会整段挤在 0；
- 温度、降水、综合以及子项展示**共用同一个 k**——这样 0/50/100 在每一层都是同一个约定，不会出现“某个指标的 0 比另一个深”；
- `k` 冻结进 config，报告 meta 留痕；它是**显示压缩参数**，不是物理常数；
- **子分不在 0~100 上平均**：先在技能变量 `s` 上加权，得到维度 `s`，再在维度/综合层做**一次**映射。否则“先映射再平均”与“先平均再映射”在非线性下半段会给出不同结果，50 的含义会漂；
- 名次、CI、显著性、冠军判定全部在原始 `s` 上算；0~100 映射只影响屏幕数字，不改变排序。

**为什么不用 `0 = 无技巧` 的标准约定**：那会让“无技巧”的模型直接显示 0，重复用户看到的“0 分”问题；而 50 中心只要**强制标注**，对非专业读者更友好。页面必须同时显示：

- 大字：`技能 −59%`（相对气候平均；正负号直接可读）；
- 小字：`指数 20`（0~100 排序用，50=气候平均）；
- 颜色：低于 50 = 橙/红“低于气候平均”；50 = 灰“与气候平均持平”；高于 50 = 蓝“优于气候平均”。

50 不允许裸奔。

### 3.4 权重：主榜只放技能，属性单列

**温度主榜**（合计 100）：

| 族 | 权重 | 成员 |
|---|---:|---|
| 总体误差 | 55 | RMSE 45 / MAE 10 |
| 阈值命中 | 25 | ±2°C 20 / ±1°C 5 |
| 形态 | 20 | 异常相关 20 |

**降水主榜**：

| 族 | 权重 | 成员 |
|---|---:|---|
| 晴雨 | 60 | ETS |
| 雨量 | 25 | 对数雨量技能 |
| 雨强 | 15 | grade_ETS |

**综合分**：`s_composite = (s_temp + s_precip) / 2`，再做一次映射。`50` 表示**两维平均技能为 0**，不保证两维各自都是 0；一正一负也会落在 50 附近，所以两维分必须同时可见。

**属性层**：MBE、bdisp、slope、raw r、POD、FAR、bias、amt_bias，权重 0，单独面板。

**权重审计**：新口径跑出来后用 `exact_variance_contribution` 检查每项真实方差贡献是否在名义权重 0.75~1.33 倍以内；超出才调整，并把调整写成价值判断。

**业务可用性副榜（可选）**：如果产品上更关心“订正偏差后能不能用”，可以另出一张副榜，按 **85% 纯技能 + 10% 偏差分 + 5% 幅度分** 合成，明确标“业务可用性（含偏差/形态）”，不与主技能榜混读。推荐主榜仍为纯技能。

### 3.5 证据层：复用 n_eff，事件数只做标注，不做第二道硬门

- 指标能不能算，继续走现有 `n_eff` / `min_sample`；
- 分块榜的入围，继续走现有 `board_block_min_rain_events` / `board_block_min_rain_days`；
- **不新增**一个与 n_eff 并行的硬门槛，也**不**把低证据分数向 50 收缩——收缩会抹平桶内真实差距，制造并列；
- 只新增两条**披露**：
  1. 桶级“独立雨事件数 / 雨日数”与 `n_eff_rain`；
  2. 若 >60% 的格子 `|ETS|≤0.05` 且 `n_eff_rain` 未过门，标“**本窗口未检出降水技巧**”。
- 低证据桶照常发布点估计 + 90% CI + “低证据”标记；排序可以让读者按 CI 看，但不再用第二个计数体系判生死。

> 关于“事件数是否重复 n_eff”：n_eff 是自相关校正后的**小时样本量**，干燥小时也计入；雨事件数数的是**独立降雨发生次数**。它们回答不同问题（“样本够不够” vs “有没有雨可评”），不是同一把尺。v2 只把事件数用于披露和现有分块门槛，不新增第二道硬门。

### 3.6 展示层：取消增益，直接显示技能分

- 删除 `index_gain` / `composite_gain` 的展示仿射；
- 直接显示 0~100 技能指数；`50` 处画一条“气候平均”基准线；
- 每个分数旁显示 `技能 +24%` / `技能 −59%`（由 `s` 直接得出，不经过压缩映射）；
- 显示 90% CI；若两家分数差小于 CI 半宽，标“统计上并列”；
- 任何“原始技能 >0 却显示 0”的路径都必须不存在。

> v2 不采用“上半段拉伸、下半段原样”的分段展示。它虽然保序，但引入了跨段间隔失真，也没有必要——技能分本身已经铺满 0~100。

## 4. 对两份评审的逐条处置

## 7. 验收：只验量表性质，不验分数落点

1. **零信息源**：构造“永远报参照”的源，每桶技能指数 50±2；这是“50=无技巧”的端到端证明。
2. **基准不变性**：所有观测整体 +0.5°C、参照同步平移，技能分与名次不变。
3. **参照敏感性**：W=10/15/30 时桶级中位技能变动 ≤5；超过则标注“参照强度不足”。
4. **无假 0**：任何 `s>s_floor` 的格，显示分 >0；每个 0 都能追溯到 `s` 低于下界/极端尾部的具体指标值。
5. **保序性**：同一桶内，原始 `s` 与显示分 Spearman=1。
6. **发散量守卫**：`Σf/Σo` 类比值 >10 的格必须走对数域；不得直接触底。
7. **缺测/无技巧/无证据三态**：ETS 缺失 → 降水 None；ETS=0 → 约 50 + “未检出技巧”；只有 amount → 降水 None。
8. **bootstrap 一致**：点估计与重采样用同一参照、同一映射；CI 中心与点估计一致。
9. **旧报告回放**：`slope-v2` 月报分数逐位不变。
10. **名次变化**：只披露（逐桶冠军变更、Spearman、并列数），不设阈值，不以旧口径为验收参考系。

**删除 v1 的“8~16 天中位 ≥40 / ≥45”和“Spearman ≥0.85/0.90”验收线**——那是用分数值验收量表，和 v1 自己批评的 λ 标定是同一类错误。

## 9. 一句话总结

**v1 的“0 分是假的”判断是对的；但 v1 的“中长期回到 49~51”是桶级聚合 + 下半段拉伸 + 未来参照造成的过度乐观。**

按 68 天实际存档、块级单元格、只用过去观测、纯技能加权，14 天温度约 **34**、降水约 **44**（且多数格 ETS≈0，应标“未检出降水技巧”）、综合约 **39**。0 分会被消灭，但低分本身是这份数据支持的结论。要区分“技能”和“业务可用性”，后者可以另出一张副榜。
