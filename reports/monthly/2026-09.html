💡 怎么看：综合分的金色须线是 90% 置信区间——须线重叠的两家， 先后在统计上还说不清；名字带 † 同理。单项指标怎么读：准确率 / 相关 r / POD / TS / ETS / 雨强ETS 越高越好，RMSE / MAE / 空报率 / 站间偏差 / 雨量误差 越低越好， MBE 越接近 0、斜率 / BIAS / 雨量比 越接近 1 越好（悬停列名有逐项说明）。 总榜的降水单项是小时（≥1mm/h）与日累计（≥1.0mm/24h）两轨拼接的对齐值， 分榜为该档原始口径；降水比温度难报得多，TS 到 0.3~0.5 已属正常水平，请按列内相对高低读。 覆盖时效是这家实际参与计算的样本最远覆盖到的提前量； 温度维与降水维分别核计，两维不等时数字后括注（如「温16·雨5」：逐日预报产品把温度维带到 16 天， 降水维仍止于逐小时的 5 天）——该行综合分的桶覆盖范围见下方「难度对齐」折叠区。

🌡️ 日榜的温度分怎么读：它是日最高、日最低各自过换算、各自评分后再取均值， 不是"先把两半指标平均再评分"。两半偏差方向相反的格子（占多数）里，|MBE| 的惩罚不会互相抵消—— 这是正确的，但均值指标列复算不出温度分（本窗口实测系统性差约 0.5 分、最坏近 5 分）。 要逐位复算，请展开行内的分半视图（日最高/最低 8 项指标原样发布），不要用均值列。

不入分：TS、晴雨准确率、漏报率、空报频率——给定样本量的 2×2 列联表只有 3 个自由度，而 ETS/POD/FAR 恰好撑满，这四个都是它们的函数 （用它们反解列联表重建 acc/ts，残差 8e−4 / 1.3e−3，全是舍入）； 加进来不增加信息，只会把基率污染请回来。雨量 RMSE 亦不入分：与雨量 MAE 桶内相关 0.97，且平方刻度把跨桶尺度差放大一倍。 雨量总量比 amt_bias 只列明细、不入分：它与 amt_mae 的桶内原始相关 实测 0.995（小时）/ 1.000（日）——两者是同一个量的两种写法；且它的子分与 降水分几乎不相关（-0.11 / +0.13）。雨量精度族 22.5% 的权重全部归 amt_mae， 同一份证据不说两遍。

某项缺数据时按剩余权重折算（缺数据 ≠ 差数据）；综合分 = 温度分与降水分各半。 小时榜与日榜之间按 2:1 合成（daily_track_weight=0.50）： 日轨的日最高/最低、日累计降水对多数源是同一份逐小时预报重新分箱，独立证据有限， 降为 1/3 可避免把"日极值"这一类信息计两遍；单轨榜与单维内合成不受影响。

综合分是"技能指数"，带两层固定的区分度缩放：14 个子分各自标定到 "桶内跨源 sd = 8 分"，但权重的平均会把离散度压到 ≈2.8 分。第一层先把维度分 各自做一次仿射缩放 g(s)=50+1.85·(s−50)； 第二层再对两维平均后的综合分做一次 g(s)=50+1.65·(s−50)。 为什么必须分两层：两维均值差 40+ 分，平均后综合分的上端被整段砍掉（维度 P99.5 已到 98，综合分 P99.5 只有 ~80）；若直接把维度分的靶点改到综合分，温度维一半 格子会被 clip 成 100——那是把问题挪个位置。两层都是冻结常数、非按本期 μ/σ 自适应，仿射且单调 ⇒ 名次与显著性判定不变；代价是 CI 宽度同比例放大—— 故"数字拉开"是显示层的（能分辨的仍只有第一梯队 vs 长尾）。

换算斜率是标定值，不是随手定的：一项指标对名次的实际影响力 = 权重 × 斜率 × 该指标在本期数据里的离散度——只声明前两个，第三个（数据的偶然分布） 就会替你决定名次。每项斜率按"子分桶内跨源 sd ≈ 8 分"在真实存档上反解 （scripts/calibrate_score_slopes.py，值随配置季度重标定）， 因此上表的权重就是各项实际话语权的近似值；"🔬 这份名次有多结实" 一节逐轨列出实测占比供核对。

"温度:降水各半"的兑现度（小时轨）： 本期综合分方差中温度贡献 36% · 降水贡献 50% · 协方差 14%（两维桶内标准差 9.31 vs 11.03 分，样本 294 格）。 50:50 是名义权重，名次上的实际话语权由两维离散度决定—— 温度:降水的宏观权重已在冠军频率敏感性里按 U(30%,70%) 扰动（）。

"温度:降水各半"的兑现度（日轨）： 本期综合分方差中温度贡献 38% · 降水贡献 42% · 协方差 20%（两维桶内标准差 9.34 vs 9.91 分，样本 298 格）。 50:50 是名义权重，名次上的实际话语权由两维离散度决定—— 温度:降水的宏观权重已在冠军频率敏感性里按 U(30%,70%) 扰动（）。

📏 「能报 3 天的和能报 15 天的」为什么能同榜：难度对齐与名次的稳健性

越往后越难报，而各家能报的天数差很多：直接平均"自己覆盖的那几档"， 只报近几天的源白拿简单档的分。本页用双向加法劈分——把「（源 × 档位）」看成 分数 = 这家水平 + 这一档难度 + 噪声，用全部格子一起估出行、列效应， 数据一格不扔，也不要求各家覆盖一致。

这份名次有多结实？ ① 格子按 √(有效样本量) 加权，过薄格子剔除（本轮剔除 2 个）； ② 换成等权口径重算，名次 Spearman = 0.99（前十换 0 家）； ③ 分数方差拆解：源间 37% · 档位难度 47% · 交互与噪声 16%——残差占比越高，"一个数字排座次"抹掉的真实差异越多； ④ 有效样本量已扣除时间自相关与跨站相关（相邻站由同一批天气系统驱动，直接相加会高估约 1.7 倍）。

🧭 各源的"起报时刻"到底是什么（口径存疑 ⚠️ 的出处）

同一个「提前 N 天」，各家用的起报锚点并不都是同一回事。 若锚点实质接近抓取时刻，声明的时效会系统性地长于实际时效——这样的源在榜上挂 ⚠️。 本轮 31 家里挂旗 7 家， 理由列在前（= 榜上 ⚠️ 悬停时看到的同一段话）；其余 24 家按语义归组， 同一句话只说一遍。 未声明存档＝早于元数据契约的历史快照（无从考证其锚点语义，不计入争议），随归档自然递减。

§02 · 理解

得分随时效衰减：谁"掉秤"掉得慢？

把每一档提前量的得分连成曲线。灰色地带是全体源的波动范围（虚线 = 中位）， 默认画总榜前三名；选源面板按源家族分组勾选，或直接点图例增删。 小时口径答"某日几点准不准"，日口径答"这一天的极值/总量准不准"， 两条曲线口径不同、不能互相比斜率；综合口径是同一提前天数上两种口径 分数各半的合成（两轨缺一即缺），与榜单下拉里的「综合 · 提前 N 天」同口径。

💡 怎么看：线向右下掉是自然规律（越远越难报）；谁在右边还站得高， 谁的长期预报就更可靠。线中断 = 该时效样本不足。

§03 · 理解

温度与降水，分别准在哪？

按提前天数（1~16 天）展开的单项指标。逐小时口径看"这一小时的 温度/雨报得如何"，日口径看"这一天的日最高/最低温与 24h 累计雨报得如何"。 默认看总榜前三名，选源面板按源家族分组勾选，或直接点图例增删； 温度与降水两页签可切换，指标下拉可换视角。

💡 怎么看：准确率/相关系数越高越好，RMSE/MAE/空报率越低越好； MBE 越接近 0 越好（正 = 习惯性报偏高，负 = 报偏低）；BIAS 越接近 1 越好。 日口径的降水为北京时自然日 24h 累计 ≥1.0mm 的晴雨； 降水比温度难报得多，TS 到 0.3~0.5 已属正常水平。

§04 · 理解

每一天的对账结果

每个格子 = 某天 × 某家预报源的当日表现，行按总榜名次排列。 绿 = 准，红 = 翻车，空白 = 数据不足。温度与降水两要素可切换， 指标下拉含两族全部指标（温度：±1/±2°C、RMSE、MAE、|MBE|； 降水为该天逐小时 ≥1mm 时雨的晴雨评分：TS/ETS/晴雨准确率/POD/FAR）。

💡 怎么看：整列发红往往是天气突变（大家都难），整行偏红才是这家整体拉胯； 降水的 TS 天然比温度准确率低一截（雨是否下在那一刻本来就难报），请按行内相对高低读。手机上格子很密，可拖动图表下方的滑块，只放大看某几天。

最近 72 小时：预报 vs 实况

口径与已知差异

① 天桶按日历对齐：「提前 N 天」= 起报日之后第 N 个自然日，两个口径同窗比较。 ② 有效样本量 n_eff 已扣除时间自相关与跨站相关，直接按站求和会高估约 1.7 倍。 降水事件证据门：n_eff 数的是"雨/无雨判定"，干燥小时占绝对多数—— 一个只覆盖十来天、只有十几场雨的源也可能凭上千个"判定"过关。因此降水维另按 独立观测事件设门（小时轨 ≥30 个 ≥1mm/h 事件、 日轨 ≥8 个 ≥1mm 雨日，同一事件不因多轮起报重复计）； 未达标的源标"样本积累中"，分数保留为参考值，但不参与名次与冠军竞争，也不发布置信区间。 入设计格子数门：样本量再厚也只等于"一个天桶里的样本多"，而名次由跨了多少个 天桶决定——每条轨道至少 4 个格子进设计 （总榜要求小时段与日段各自达标，1+1 格不再算"综合"）。 ③ 总榜加权：每个格子按 √(两维有效样本量的较小者) 加权，过薄格子剔出设计； 小时段与日段的宏观权重为 1:0.5 （日轨独立性有限，降为 1/3）。 ④ 逐小时降水口径：各源入库口径不同（原生序列透传 / 雨率近似 / 累计均摊 / 移位标定）， 已在快照与代码中留档并定期标定复核。 ⑤ 日聚合门槛：只在观测与预报两侧当日非缺测小时数都达标（≥20/24）的天上比较—— 降水全缺测的样本绝不折算成"预报无雨"。 ⑥ 逐日预报补位：逐小时够不着的日子用该源自带的逐日预报补位参与按天评估； 逐小时指标与排行榜永不掺入日预报反推的样本。逐日块只接可信要素（缺测要素整列为 null，绝不折算）； 只延展了部分要素的源（如中科星图逐日块只接温度），其补位天桶的综合分仍判"缺一即缺"， 只有温度分可见——覆盖列与分时效榜会把这种情况如实标出。逐源逐格的构成见下方 「日轨的样本是从哪来的」披露表。⑦ 残缺快照默认排除：接口只返回部分分片的快照不参与评估（本窗口已排除 MSN天气 19 份）。⑧ 实况自 2026-09-01 起接入，覆盖率按各站实际有实况的时段计算。

🔬 这份名次有多结实？——诊断层的硬数字

同榜的 27 家，其实是几份独立证据？

各家预报的是同一批天气系统，它们的误差天然高度相关。 实测两两相关均值 ρ̄ = 0.5913， 按 k_eff = m/(1+(m−1)ρ̄) 折算后的有效独立信源数约 1.65 家 ——榜单上看上去是 27 份证据，折算后只相当于约 1.65 份。这直接决定"第一名领先第二名"这句话的含金量。 显著性检定（† 标记）采用 max-T 单步（族内极值）多重比较校正：把多重性 放进统计量本身（看"这一族里最极端的那次偏离"在重采样下的分布），而不是把阈值 除以比较家数——在本项目 R = 500 的重采样分辨率下， 后者会让检验恒不显著（静默失效）。 括号里的 k_eff = 1.65 是并列披露：27 份 证据折算后只相当于约 1.65 份独立信源，判断"第一名领先" 的可信度时应据此打折。

留一源：这张榜是不是被一两家撑着？

📖 名词小词典
起报 / 起报快照
预报发布的那一刻叫"起报"。每次起报的"未来 16 天逐小时预报"原样存档封存，等真实天气发生后对账——预报不能事后改，检验才算数。
时效（提前 N 天）
有效时刻 − 起报时刻 = "提前多久做的预报"，按日历天分桶；每个桶里同难度比较。
综合得分 / 温度分 / 降水分
多个指标压缩成 0~100：温度 8 项、降水 6 项加权（换算斜率按数据标定），综合 = 两者各半再过第二层技能指数缩放；缺项按剩余权重折算。分数只用于排序，绝对值不可跨榜、跨期解读。
难度对齐（总榜）
先把每一档提前量有多难算出来、统一扣掉再比（双向加法模型），能报 3 天的和能报 15 天的同榜也不吃亏。
覆盖时效
该源实际参与计算的样本最长覆盖到提前第几天。温度维与降水维分别核计：榜上数字取两维最远值，两维不一致时括注各自的天数（逐日预报块通常只延展温度维，如中科星图温度至 16 天、降水仍止于逐小时的 5 天）。可用时效越少，总榜平均所依据的"桶"越少。
90% 置信区间与 †
对评估窗口内的天做分块重采样 500 次重算榜单得到的波动范围。名字带 † = 与第一名的差距经 max-T（单步族内极值）多重比较校正后仍与 0 分不开——不宜过度解读名次先后。
有效样本量 n_eff
逐小时误差强自相关，名义 n 会把同一信息重复计数；n_eff 按"每天真正带来多少新信息"折算，跨源比较请以它为准。悬停"覆盖"列可看四个 n_eff 的明细。
降水事件证据
观测中真正达到阈值的独立事件数（小时 ≥1mm/h、日 ≥1mm），按 站×时刻 / 站×日 去重。它是"有没有足够多的雨可评"的证据门，与 n_eff 的"判定样本量"不是一回事：样本积累中的源分数仅作参考。
RMSE / MAE / MBE
温度误差的典型大小（°C，越小越好）：RMSE 对偶发大误差惩罚更重；MAE 是最朴素的"平均差多少度"；MBE 正 = 习惯性报偏高，负 = 报偏低。
相关系数 r / 回归斜率
r 越接近 1 越能跟上天气的"节奏"；斜率 >1 = 起伏幅度偏小（该热不热），<1 = 反应过激。
准确率（±1°C / ±2°C）
预报与实况相差不超过 1°C（或 2°C）的样本占比，越高越好。
命中率（POD）/ 空报率（FAR）
POD：真下雨的次数里预报也报出的比例（越高越好）；FAR：报了雨却没下的比例（"狼来了"次数，越低越好）。
TS / ETS 评分
命中 ÷（命中 + 空报 + 漏报），0~1，同时奖励报中、惩罚误报；ETS 对"瞎蒙也能蒙对"做过随机命中校正，更公平。
频率偏差（BIAS）
报雨次数 ÷ 实际下雨次数。=1 频率正好；>1 爱报雨；<1 不爱报雨。
雨量误差 / 雨量比（amt_mae / amt_bias）
相对口径的雨量精度：量级误差 = Σ|预报−实况| ÷ Σ实况（越低越好）；总量比 = 预报总雨量 ÷ 实况总雨量（=1 正好，>1 总量偏多）。相对口径让小时轨与日轨可用同一把尺比较。
雨强分辨力（雨强 ETS）
中雨/大雨档（1h：2~4.9、5~9.9 mm/h；24h：≥10、≥25 mm）的 ETS——晴雨报对之外，雨下到没到量级也报得出来才算高分。
站间偏差（mbe_bdisp）
各站系统偏差的离散度（°C）：越小 = 这家在同一场天气的不同站点表现越一致；池化的 |MBE| 会把站间差异平均掉，这一项专门暴露它。
日雨评分（TS/ETS）
降水分的口径是北京时自然日 24h 累计雨量 ≥1.0mm 记"有效降水日"（业务惯用口径）；24h 累计让毛毛雨超报在求和中自然抵消。
观测覆盖率
评估窗口内成功抓到实况的小时占比（实况接入前的时段不算缺失）；本窗口实况自 2026-09-01 起。
