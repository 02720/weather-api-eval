⏱️ 时效 = 提前量
预报是提前多久做的。总榜把所有时效的样本合并算总账；「提前 N 天」分榜则一档一张榜——提前 1 天大家都准，提前 10 天谁守得住，切着看才知道。
🏅 综合得分
温度分（7 项指标加权）与降水分（6 项指标加权）各算一个 0~100 的分，再取平均。一项"瘸腿"拿不了高分，构成明细见排行榜下方。
🌡️ 温度准确率（±2°C）
预报温度与实况相差 不超过 2°C 就算报准。比例越高越好，100% = 满分。
📉 温度误差（RMSE）
温度平均报错了多少 °C，越小越好，0 = 完美。它对"偶尔离谱的大误差"更敏感。
🌧️ 日雨评分（TS）
按天结算的"下没下雨"报对程度（24h 累计 ≥mm 算雨日；0~1），同时惩罚漏报和瞎报，越高越好。

🏅 预报源排行榜

🌡️ 温度分（7 项，权重和 100%）

指标权重0~100 换算
±2°C 准确率25%百分比直接入分
RMSE 误差换算分25%100 − RMSE×5（0°C 记 100 分，每多 0.2°C 扣 1 分）
相关系数 r15%r×100（起伏节奏的同步程度）
±1°C 准确率10%百分比直接入分（更严格的命中口径）
MAE 误差换算分10%100 − MAE×5（典型误差，对偶发大误差不敏感）
偏差换算分10%100 − |MBE|×10（无系统性偏高/偏低 = 满分）
回归斜率换算分5%100 − |斜率−1|×100（冷热幅度恰如其分 = 满分）

不入分：RSS、χ²——χ²=RMSE²、RSS=n×χ²，是样本量的函数而非预报技巧（数值仍可在进阶区明细表查看）。

🌧️ 降水分（5 项，权重和 100%；按天 24h 累计 ≥mm 口径）

指标权重0~100 换算
晴雨 ETS 评分35%ETS×100（对“瞎蒙也能蒙对”做过校正，技巧首位）
晴雨 TS 评分25%TS×100（报中/空报/漏报一账清）
命中率 POD15%百分比直接入分（漏报少）
空报率换算分15%100 − FAR（不喊“狼来了” = 满分）
频率偏差换算分10%100 − |BIAS−1|×100（报雨频率恰如其分 = 满分）

不入分：晴雨准确率（干燥气候下"全答无雨"也能拿高分，主要由气候基率决定而非技巧， ETS 已做过基率校正）、漏报率（=100−命中率）、空报频率（与空报率同族仅分母不同）、 雨量 RMSE/MAE/MBE（由个别强降水时段主导、随样本期气候波动大，跨源比较不公平）。 命中率权重低于空报率+偏差之和——评分不奖励"多报占便宜"。

各子分都截断到 0~100；某项缺数据时按剩余权重折算（"存疑不计亏"口径：缺数据≠差数据， 不让单一缺项把整行踢出局，也不因缺项额外扣分）——缺失的维度在榜单里以 — 显示，读者可自行判断。 综合分 = 温度分与降水分各占一半。把"报得准、误差小、节奏对、不偏科、雨报得实"分别记账再合并，比只用一两个指标更能区分真实水平。 总榜与分榜用同一套桶得分：分榜只取该天桶，总榜把各桶得分等权平均。

📖 名词小词典

页面里出现的术语，全部用大白话解释一遍。

起报 / 起报快照
预报发布的那一刻叫"起报"。我们把每次起报的"未来 16 天逐小时预报"原样存档封存，等真实天气发生后再对账——预报不能事后改，检验才算数。
时效（lead）
有效时刻 − 起报时刻，即"提前多久做的预报"。"3 天时效" = 提前 3 天报的。
天桶
把时效按天分组：提前 1~24 小时算"第 1 天桶"，25~48 小时算"第 2 天桶"，以此类推。
综合得分 / 温度分 / 降水分
把多个指标压缩成一个 0~100 的总分方便排名。温度分 = 7 项温度指标（±2°C/±1°C 准确率、RMSE/MAE 换算分、相关系数、偏差分、斜率分）按 25/25/15/10/10/10/5 加权；降水分 = 6 项降水指标（TS、ETS、晴雨准确率、命中率、空报率换算分、频率偏差分）按 30/25/15/15/10/5 加权；综合得分 = 两者均分。某项缺数据按剩余权重折算。总榜与分时效榜用同一套公式，区别只在参与计算的样本。点开排行榜的「评分构成」可看每个指标的换算公式。
为什么有的指标不进综合分
χ²=RMSE²、RSS=样本量×χ²，是样本量的函数而非预报技巧；漏报率 = 100−命中率（纯重复）；空报频率与空报率同族（仅分母不同）；雨量 RMSE/MAE/MBE 由个别强降水时段主导、随当期气候波动大，跨源比较不公平——它们照常计算，只是不参与打分，可在进阶区明细表查看。
总榜（全时效汇总）
把该源在每个「提前 N 天」档的得分做等权平均后的总排行，回答"综合来看谁最准"。每个源先在自己的每个可用时效各得一分、再跨时效平均——预报难度随时效上升，这样"只提供短时效"的源不再因样本构成偏"易"而占便宜；可用时效数本身也是信息，请结合「覆盖时效」列解读。要同难度硬碰硬，切「提前 N 天」分榜。
覆盖时效
该源在本评估窗口内实际参与指标计算的样本（预报与实况两侧同时有值）中最长覆盖到提前第几天，按"温度 / 降水"两条轨道分别统计（向上取整到天；取最大值，不代表逐天连续覆盖）。受三件事限制：源本身的最长时效，"起报 + 时效"是否已落进可对账的时段，以及序列尾部缺测（尾部全是 null 的时段不参与计算，也不计入覆盖）。总榜把各时效等权平均，可用时效数越少，平均所依据的"桶"就越少。
90% 置信区间与显著性
把评估窗口内的天做有放回重采样（块长 1 天， 次），每次都重算一遍完整榜单，得到综合分的波动范围——区间越窄说明分数越"站得稳"。名字带 † 表示该源与第一名的得分差在 90% 置信下与 0 分不开（差异不显著）：两者谁先谁后更多是抽样运气，不宜过度解读。样本期只有一两周时区间天然很宽，随数据积累收窄。
有效样本量 n_eff 与门槛
逐小时误差强自相关（这一小时的预报误差和上 hour 高度相似），名义样本对数 n 会把同一信息重复计数——n_eff 按"每天真正带来多少新信息"折算（n·(1−ρ)/(1+ρ)），跨源比较请以它为准。总榜另设入围门槛 n_eff ≥ ：未达标的源列"样本积累中"，不参与冠军竞争。
日雨评分（TS/ETS，按天轨道）
降水入分口径为北京时自然日 24h 累计、日雨量 ≥mm 记"有效降水日"（业务惯用口径）。逐小时 ≥0.1mm 的口径下数值模式普遍每小时报微量降水（drizzle bias），实测超报最高 15 倍、所有源 ETS 都接近 0、评分失去区分度；24h 累计让毛毛雨在求和中自然抵消。逐小时晴雨指标仍在进阶区保留为诊断视图。
提前量档与分时效排行榜
把时效按天分档（提前 1~24 小时 = 第 1 档…），每档一张排行榜。预报难度随时效上升，同档内比较对各家才是同难度的。同一预报源在短时效可能领先、长时效掉队，切档对比才能看出谁"衰减得慢"。
RMSE（均方根误差）
温度误差的"典型大小"，单位 °C，越小越好。比起 MAE，它对偶尔的大误差惩罚更重。
MAE（平均绝对误差）
每次预报误差绝对值的平均，单位 °C，越小越好。最朴素的"平均差多少度"。
MBE（平均偏差）
预报 − 实况的平均值。正数 = 习惯性报偏高，负数 = 报偏低，接近 0 最好。
RSS（残差平方和）
所有样本误差的平方加总（°C²）。是 RMSE 的"未开方、未平均"版本，样本越多天然越大，只适合同一样本数的横向对比。
χ²（卡方）
误差平方的平均（°C²），即 MSE。与 RMSE 的关系：RMSE = √χ²。越小越好。
相关系数 r
预报与实况起伏的同步程度（−1~1）。越接近 1，预报越能跟上天气的"节奏"；接近 0 = 报了个寂寞。
回归斜率
以预报为横轴、实况为纵轴做回归的斜率。>1 = 预报的起伏幅度偏小（该热不热该冷不冷）；<1 = 预报反应过激；=1 最理想。
准确率（±1°C / ±2°C）
预报与实况相差不超过 1°C（或 2°C）的样本占比，越高越好。
晴雨
把降水简化成是非题：降水量 ≥ 0.1mm 算"有雨"，否则"无雨"。
晴雨准确率
上述是非题"答对"的比例（报有雨确实下了 + 报没雨确实没下），越高越好。
命中率（POD）
实际真的下雨的次数里，预报也报雨的比例。越高 = 漏报越少。
空报率（FAR）
预报说会下雨的次数里，实际没下的比例。越低越好（"狼来了"次数）。
空报频率（POFD）
实际没下雨的次数里，预报却报了雨的比例（与空报率分母不同）。越低越好。
漏报率
实际下雨但预报没报出来的比例，越低越好。与命中率互补：漏报率 = 1 − POD。
TS 评分
命中 ÷（命中 + 空报 + 漏报），0~1。降水检验最常用的综合分，同时奖励报中、惩罚误报。
ETS 评分
对 TS 做"随机命中校正"的版本（0~1）。考虑"瞎蒙也能蒙对一部分"，ETS 更公平：瞎蒙的预报 ETS≈0，好预报才为正。
频率偏差（BIAS）
报雨次数 ÷ 实际下雨次数。=1 频率正好；>1 爱报雨；<1 不爱报雨。
雨量误差（RMSE / MAE / MBE）
不只看下没下，还看预报的降水量数值差多少（mm），越小越好。降水数值比晴雨难报得多。
雨强分级（1h 口径）
按每小时雨量分档检验：小雨(0.1~1.9mm/h)、中雨(2~4.9)、大雨(5~9.9)、暴雨(10~19.9)、大暴雨(≥20)。每档可算全套晴雨类指标。
累计分级（24h 口径）
按日累计雨量"达到某档以上"检验：≥0.1（小雨以上）、≥10（中雨以上）、≥25（大雨以上）、≥50（暴雨以上）、≥100（大暴雨以上）、≥250mm（特大暴雨以上）。
样本数 n
参与指标计算的"预报-实况"对数。n 或有效样本量 n_eff < 5 时本报告判"样本不足"，不下结论（显示 —）。逐小时数据里 n 明显大于 n_eff（同一信息被相邻小时重复计数），比较"谁的信息更足"请看 n_eff。
观测覆盖率
评估窗口内成功抓到实况的小时占比。分母按各站实际有实况的时段计算（实况接入前的时段不算缺失）；覆盖率低会让指标样本变少。
起报锚点（各源差异）
计算"提前量"的参照时刻。多数源锚定真实起报轮次或抓取时刻；Open-Meteo 不回显真实轮次，锚点是北京时"当日 00:00"且每天只封存 1 份快照——同一「提前 N 天」桶内各源的实际难度与样本新鲜度因此略有差异（详见"口径与已知差异"）。
