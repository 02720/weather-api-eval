不入分：TS、晴雨准确率、漏报率、空报频率——给定样本量的 2×2 列联表只有 3 个自由度，而 ETS/POD/FAR 恰好撑满，这四个都是它们的函数 （用它们反解列联表重建 acc/ts，残差 8e−4 / 1.3e−3，全是舍入）； 加进来不增加信息，只会把基率污染请回来。雨量 RMSE 亦不入分：与雨量 MAE 桶内相关 0.97，且平方刻度把跨桶尺度差放大一倍。

某项缺数据时按剩余权重折算（缺数据 ≠ 差数据）；综合分 = 温度分与降水分各半。

综合分是"技能指数"，带固定的区分度缩放：15 个子分各自标定到 "桶内跨源 sd = 8 分"，但权重的平均会把综合分的离散度压到 ≈2.8 分、全榜挤成 一条窄带。故在加权之后统一做一次仿射缩放 g(s)=50+2.66·(s−50)， 把综合分的桶内跨源 sd 拉回 8 分。它是冻结常数、非按本期 μ/σ 自适应， 仿射且单调 ⇒ 名次与显著性判定不变；代价是 CI 宽度同比例放大—— 故"数字拉开"是显示层的（能分辨的仍只有第一梯队 vs 长尾）。

换算斜率是标定值，不是随手定的：一项指标对名次的实际影响力 = 权重 × 斜率 × 该指标在本期数据里的离散度——只声明前两个，第三个（数据的偶然分布） 就会替你决定名次。每项斜率按"子分桶内跨源 sd ≈ 8 分"在真实存档上反解 （scripts/calibrate_score_slopes.py，值随配置季度重标定）， 因此上表的权重就是各项实际话语权的近似值；"🔬 这份名次有多结实" 一节逐轨列出实测占比供核对。

"温度:降水各半"的兑现度（小时轨）： 本期综合分方差中温度贡献 20% · 降水贡献 65% · 协方差 16%（两维桶内标准差 3.96 vs 7.22 分，样本 305 格）。 50:50 是名义权重，名次上的实际话语权由两维离散度决定—— 温度:降水的宏观权重已在冠军频率敏感性里按 U(30%,70%) 扰动（）。

📏 「能报 3 天的和能报 15 天的」为什么能同榜：难度对齐与名次的稳健性

越往后越难报，而各家能报的天数差很多：直接平均"自己覆盖的那几档"， 只报近几天的源白拿简单档的分。本页用双向加法劈分——把「（源 × 档位）」看成 分数 = 这家水平 + 这一档难度 + 噪声，用全部格子一起估出行、列效应， 数据一格不扔，也不要求各家覆盖一致。

这份名次有多结实？ ① 格子按 √(有效样本量) 加权，过薄格子剔除（本轮剔除 4 个）； ② 换成等权口径重算，名次 Spearman = 0.98（前十换 1 家）； ③ 分数方差拆解：源间 27% · 档位难度 58% · 交互与噪声 15%——残差占比越高，"一个数字排座次"抹掉的真实差异越多； ④ 有效样本量已扣除时间自相关与跨站相关（相邻站由同一批天气系统驱动，直接相加会高估约 1.7 倍）。

🧭 各源的"起报时刻"到底是什么（口径存疑 ⚠️ 的出处）

同一个「提前 N 天」，各家用的起报锚点并不都是同一回事。 若锚点实质接近抓取时刻，声明的时效会系统性地长于实际时效——这样的源在榜上挂 ⚠️。 本轮 28 家里挂旗 6 家， 理由列在前（= 榜上 ⚠️ 悬停时看到的同一段话）；其余 22 家按语义归组， 同一句话只说一遍。 未声明存档＝早于元数据契约的历史快照（无从考证其锚点语义，不计入争议），随归档自然递减。

§02 · 理解

得分随时效衰减：谁"掉秤"掉得慢？

把每一档提前量的得分连成曲线。灰色地带是全体源的波动范围（虚线 = 中位）， 默认画总榜前三名；选源面板按源家族分组勾选，或直接点图例增删。 小时口径答"某日几点准不准"，日口径答"这一天的极值/总量准不准"， 两条曲线口径不同、不能互相比斜率；综合口径是同一提前天数上两种口径 分数各半的合成（两轨缺一即缺），与榜单下拉里的「综合 · 提前 N 天」同口径。

💡 怎么看：线向右下掉是自然规律（越远越难报）；谁在右边还站得高， 谁的长期预报就更可靠。线中断 = 该时效样本不足。

§03 · 理解

温度与降水，分别准在哪？

按提前天数（1~16 天）展开的单项指标。逐小时口径看"这一小时的 温度/雨报得如何"，日口径看"这一天的日最高/最低温与 24h 累计雨报得如何"。 默认看总榜前三名，选源面板按源家族分组勾选，或直接点图例增删； 温度与降水两页签可切换，指标下拉可换视角。

💡 怎么看：准确率/相关系数越高越好，RMSE/MAE/空报率越低越好； MBE 越接近 0 越好（正 = 习惯性报偏高，负 = 报偏低）；BIAS 越接近 1 越好。 日口径的降水为北京时自然日 24h 累计 ≥1.0mm 的晴雨； 降水比温度难报得多，TS 到 0.3~0.5 已属正常水平。

§04 · 理解

每一天的对账结果

每个格子 = 某天 × 某家预报源的当日表现，行按总榜名次排列。 绿 = 准，红 = 翻车，空白 = 数据不足。温度与降水两要素可切换， 指标下拉含两族全部指标（温度：±1/±2°C、RMSE、MAE、|MBE|； 降水为该天逐小时 ≥1mm 时雨的晴雨评分：TS/ETS/晴雨准确率/POD/FAR）。

💡 怎么看：整列发红往往是天气突变（大家都难），整行偏红才是这家整体拉胯； 降水的 TS 天然比温度准确率低一截（雨是否下在那一刻本来就难报），请按行内相对高低读。手机上格子很密，可拖动图表下方的滑块，只放大看某几天。

§05 · 亲眼看看

最近 72 小时：预报 vs 实况

黑线 = 气象站实测气温，彩线 = 所选预报源；灰蓝宽柱 = 站点实测降水， 实心窄柱 = 该源同时刻的预报降水（右轴）——两根柱子对得越齐，降雨时段报得越准。

§06 · 亲眼看看

同一个预报，在不同站点的表现

选一家预报源，看它在各观测站的表现差异（地形、气候不同会有差异）； 指标下拉含温度、降水两族的全部已评测指标，虚线 = 全体源在该站的中位水平。 坐标轴按指标类型取刻度：百分比 0~100、评分 0~1、误差从 0 起、MBE 正负对称、BIAS 标出「=1 正好」。

⚙️ 这份报告是怎么来的（机制 · 口径 · 可审计性）
  1. 每天 06:00 / 13:00 / 20:00（北京时）自动抓取 4 个气象站的实况，以及各家预报源当时发布的起报数据。
  2. 预报一旦发布立即原样封存，等真实天气发生后逐小时对账——先封存、后验证，杜绝"事后改预报"。
  3. 本页每次都用保留期内的全部累计数据重新计算（评估由开源库 cyeva 完成），打开永远是"数据起点至今"的最新结果——总榜跨月累计，每月 1 号不清零、不退回"样本积累中"。
  4. 每月 1 号把上个月冻结成月度归档，回答"那个自然月谁最准"，永久可查（见页脚）。

口径与已知差异

① 天桶按日历对齐：「提前 N 天」= 起报日之后第 N 个自然日，两个口径同窗比较。 ② 有效样本量 n_eff 已扣除时间自相关与跨站相关，直接按站求和会高估约 1.7 倍。 ③ 总榜加权：每个格子按 √(两维有效样本量的较小者) 加权，过薄格子剔出设计。 ④ 逐小时降水口径：各源入库口径不同（原生序列透传 / 雨率近似 / 累计均摊 / 移位标定）， 已在快照与代码中留档并定期标定复核。 ⑤ 日聚合门槛：只在观测与预报两侧当日非缺测小时数都达标（≥20/24）的天上比较—— 降水全缺测的样本绝不折算成"预报无雨"。 ⑥ 逐日预报补位：逐小时够不着的日子用该源自带的逐日预报补位参与按天评估； 逐小时指标与排行榜永不掺入日预报反推的样本。逐日块只接可信要素（缺测要素整列为 null，绝不折算）； 只延展了部分要素的源（如中科星图逐日块只接温度），其补位天桶的综合分仍判"缺一即缺"， 只有温度分可见——覆盖列与分时效榜会把这种情况如实标出。⑦ 残缺快照默认排除：接口只返回部分分片的快照不参与评估（本窗口已排除 MSN天气 17 份）。⑧ 实况自 2026-08-25 起接入，覆盖率按各站实际有实况的时段计算。

存档完整性（可自行核验）

本轮 9566 份存档内容的哈希被聚合成一个 Merkle 根： 41be98574be1854adaee3b5d2c743d8b38a340f90ccd6955304c089a0c3dfcaf。 任何人克隆仓库后运行 python -m weather_eval verify 即可重算比对。 能力的边界要一并说清：校验会比对"重算的内容哈希"与"封存时盖下的 内嵌哈希"（5471 份带内嵌哈希）， 因此误操作编辑、git 冲突残留、工具链自动格式化都能被抓到； 但"改内容 + 正确重算哈希 + 重跑报告刷新清单"这条完整攻击链抓不到—— 堵住它需要仓库之外的不可变锚点（根另行留档或签名），本项目目前没有做。

🔬 这份名次有多结实？——诊断层的硬数字

同榜的 28 家，其实是几份独立证据？

各家预报的是同一批天气系统，它们的误差天然高度相关。 实测两两相关均值 ρ̄ = 0.5802， 按 k_eff = m/(1+(m−1)ρ̄) 折算后的有效独立信源数约 1.68 家 ——榜单上看上去是 28 份证据，折算后只相当于约 1.68 份。这直接决定"第一名领先第二名"这句话的含金量。 显著性检验（† 标记）当前用的是保守口径 m （m = 29，k_eff = 1.68）： 保守口径宁可多说"说不清"，因为往 k_eff 方向放松会增加被判"与冠军有显著差异"的家数。

留一源：这张榜是不是被一两家撑着？

逐个剔除入设计的源重算总榜，看名次怎么动。 本轮参与桥接的源 28/28 家。 对名次影响最大的一家：MSN天气 （剔掉后与冠军的名次相关性 0.9982、前十换 1 家）。

有效时刻 − 起报时刻 = "提前多久做的预报"，按日历天分桶；每个桶里同难度比较。
综合得分 / 温度分 / 降水分
多个指标压缩成 0~100：温度 5 项、降水 4 项加权（换算斜率按数据标定），综合 = 两者各半；缺项按剩余权重折算。分数只用于排序，绝对值不可跨榜、跨期解读。
难度对齐（总榜）
先把每一档提前量有多难算出来、统一扣掉再比（双向加法模型），能报 3 天的和能报 15 天的同榜也不吃亏。
覆盖时效
该源实际参与计算的样本最长覆盖到提前第几天。温度维与降水维分别核计：榜上数字取两维最远值，两维不一致时括注各自的天数（逐日预报块通常只延展温度维，如中科星图温度至 16 天、降水仍止于逐小时的 5 天）。可用时效越少，总榜平均所依据的"桶"越少。
90% 置信区间与 †
对评估窗口内的天做分块重采样 500 次重算榜单得到的波动范围。名字带 † = 与第一名的差距经 Holm–Bonferroni 校正后仍与 0 分不开——不宜过度解读名次先后。
有效样本量 n_eff
逐小时误差强自相关，名义 n 会把同一信息重复计数；n_eff 按"每天真正带来多少新信息"折算，跨源比较请以它为准。
RMSE / MAE / MBE
温度误差的典型大小（°C，越小越好）：RMSE 对偶发大误差惩罚更重；MAE 是最朴素的"平均差多少度"；MBE 正 = 习惯性报偏高，负 = 报偏低。
相关系数 r / 回归斜率
r 越接近 1 越能跟上天气的"节奏"；斜率 >1 = 起伏幅度偏小（该热不热），<1 = 反应过激。
准确率（±1°C / ±2°C）
预报与实况相差不超过 1°C（或 2°C）的样本占比，越高越好。
命中率（POD）/ 空报率（FAR）
POD：真下雨的次数里预报也报出的比例（越高越好）；FAR：报了雨却没下的比例（"狼来了"次数，越低越好）。
TS / ETS 评分
命中 ÷（命中 + 空报 + 漏报），0~1，同时奖励报中、惩罚误报；ETS 对"瞎蒙也能蒙对"做过随机命中校正，更公平。
频率偏差（BIAS）
报雨次数 ÷ 实际下雨次数。=1 频率正好；>1 爱报雨；<1 不爱报雨。
雨量误差 / 雨量比（amt_mae / amt_bias）
相对口径的雨量精度：量级误差 = Σ|预报−实况| ÷ Σ实况（越低越好）；总量比 = 预报总雨量 ÷ 实况总雨量（=1 正好，>1 总量偏多）。相对口径让小时轨与日轨可用同一把尺比较。
雨强分辨力（雨强 ETS）
中雨/大雨档（1h：2~4.9、5~9.9 mm/h；24h：≥10、≥25 mm）的 ETS——晴雨报对之外，雨下到没到量级也报得出来才算高分。
站间偏差（mbe_bdisp）
各站系统偏差的离散度（°C）：越小 = 这家在同一场天气的不同站点表现越一致；池化的 |MBE| 会把站间差异平均掉，这一项专门暴露它。
日雨评分（TS/ETS）
降水分的口径是北京时自然日 24h 累计雨量 ≥1.0mm 记"有效降水日"（业务惯用口径）；24h 累计让毛毛雨超报在求和中自然抵消。
观测覆盖率
评估窗口内成功抓到实况的小时占比（实况接入前的时段不算缺失）；本窗口实况自 2026-08-25 起。
